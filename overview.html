04

怎么装

两个场景 · 复制命令即可 · 全程不超过 5 分钟
场景 A

从零搭一个新平台

~ — bash
# 1. 新建空目录
$ mkdir my-platform && cd my-platform

# 2. 远程 bootstrap 出骨架（自动 clone 临时 kit → scaffold → 清理）
$ bash <(curl -sSL https://raw.githubusercontent.com/0xFivis/agentic-mesh-arch-kit/main/bootstrap.sh) --name my-platform --with-examples

# 3. 装 AI 配置（4 厂商一次到位）
$ bash <(curl -sSL https://raw.githubusercontent.com/0xFivis/agentic-mesh-ai-kit/main/bootstrap.sh) --vendor all

# 4. 加第一个服务（scaffold 已把 new-service.sh 投递到 .arch-kit/，直接用）
$ bash .arch-kit/new-service.sh --type api --name orders --bctx bctx-orders

# 想钉版本？前面加 KIT_REF=v1.2.0 即可
产出：完整 monorepo · 8 章架构 · 9 项标准 · contracts/apps/ops/testing 全套 · 15 skills × 4 vendors · MCP/Hooks 接通 · Spec-Kit 已 init · CI workflows 落位
场景 B

给已有仓库接入 AI 配置（不动你现有目录）

your-existing-repo — bash
# 在你的现有仓根目录
$ bash <(curl -sSL https://raw.githubusercontent.com/0xFivis/agentic-mesh-ai-kit/main/bootstrap.sh) --vendor all
新增：AGENTS.md（L1 入口）· .claude/ .cursor/ .codex/ .github/ 四套配置 · 自动在 apps/ packages/ docs/ contracts/ 等 10 个固定目录铺 L2 AGENTS.md（已存在的绝不覆盖）。其他文件零改动。
05

日常工作流

一个需求从 Intake 到复盘的完整旅程 · 蓝=普通步骤 · 橙=不可逆 Gate · 紫=横切
T0需求收敛成可执行 spec（范围 / 验收 / 风险 / 约束）PO + TL/speckit.specify [+ /speckit.clarify] + tech-intake（spec.md 二次自检 · 非必选）
T1识别变更涉及的 BC × 服务 × 契约 × 数据，标注架构增量架构师bc-impact-map → impact-analysis.md
T2 ⚑服务详设 + 数据模型 + 契约（OpenAPI / Schema / 数据迁移）架构师 + 服务 Owner 全签/speckit.plan + /speckit.checklist + /speckit.analyze
T3详设拆 task · 明确依赖与并行度TL approve/speckit.tasks + /speckit.taskstoissues
T4.1单 task 技术方案 + 自测策略 + 5 条 checklistTL（5 条全过）task-plan-drafting + gate-checklist
T4.2实现代码 + 写测试 + 跑自测 + 推 PRCI 全绿/speckit.implement + 4-Phase 嵌套 + self-review-agent + hooks
T4.3PR review · 5 红旗 + 架构红线Reviewer（AI ≠ approve）reviewer subagent（isolated context）+ gate-checklist（review 模式）
T4.4QA 验收 · 4 象限测试矩阵（与 T4.5 可并行）QAqa-cases（专职 QA 驱动）
T4.5准生产 / 灰度验证业务流是否符合 PO 预期PO + TL— （触发回写③：服务设计反馈）
T5 ⚑起草发布方案 + 回滚方案 · 按灰度策略上线Release Ownerrelease-canary → release.md + rollback.md
T6上线后窗口期观测指标 / 告警 / 业务异常SRE— （观测报告：指标快照 + 异常清单）
T7 ⚑audit checklist 系统复盘 · 沉淀 memoryEng Leadretro-audit → retro.md + Action Items + memory 沉淀
RSTD/ADR 治理 + 红线监控（横切 · 可与任意步骤并行）架构组 / 标准组std-writing / adr-writing / data-redline（/speckit.constitution 算半个）
